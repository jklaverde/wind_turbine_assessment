# Wind Turbine Anomaly Detection

An end-to-end ML pipeline that ingests wind turbine sensor data, trains a binary
classifier to detect potential mechanical or thermal failures, and exposes predictions
through a production-ready REST API.

This project is part of the **From Model to Production** series and is designed to
integrate with [windmill_scanner](../windmill_scanner) — a real-time turbine monitoring
dashboard that calls this API on every sensor beat.

## How It Works

```
Kaggle dataset
      │
      ▼
┌─────────────────────────────────────────────────────┐
│  pipeline.py  (runs once at build time)             │
│                                                     │
│  1. Download  generator_temperature from Kaggle     │
│  2. Clean     drop NaN, negatives, duplicates       │
│  3. Impute    add noise_level [35–110 dB]           │
│               add humidity   [10–100 %RH]  seed=42  │
│  4. Label     score-based failure rule (see below)  │
│  5. Split     70 / 20 / 10  stratified              │
│  6. Train     RandomForestClassifier                │
│  7. Save      model/wind_turbine_model.joblib       │
└─────────────────────────────────────────────────────┘
      │
      ▼
FastAPI service  →  POST /api/v1/predict
                    POST /api/v1/predict/batch
                    GET  /api/v1/health
```

### Failure Labeling Rule

Labels are generated by a deterministic scoring function applied to the training data:

```python
def label_failure(row) -> int:
    score = 0
    if row["temperature"]  > 90:  score += 3   # thermal stress (highest weight)
    if row["humidity"]     > 85:  score += 2
    if row["noise_level"]  > 75:  score += 2
    return 1 if score >= 3 else 0               # failure if score >= 3
```

Expected anomaly rate: **~19%** of records labeled as failures.

### Model

**Random Forest Classifier** (`sklearn`, `class_weight='balanced'`)

- Handles the non-linear decision boundaries created by the scoring logic
- `predict_proba` provides calibrated failure probabilities natively
- `class_weight='balanced'` compensates for the ~19%/81% class imbalance
- Primary evaluation metrics: **Recall** and **ROC-AUC**

## Quickstart — Local Development

### 1. Clone and set up the virtual environment

```bash
git clone <repo-url>
cd wind_turbine_assessment

python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Configure Kaggle credentials

The pipeline downloads the dataset from Kaggle on first run. You need a Kaggle API key:

1. Go to [kaggle.com/settings](https://www.kaggle.com/settings) → **API** → **Create New Token**
2. Place the downloaded `kaggle.json` in:
   - Windows: `C:\Users\<you>\.kaggle\kaggle.json`
   - macOS/Linux: `~/.kaggle/kaggle.json`

> After the first run the dataset is cached locally — credentials are not needed again.

### 3. Run the pipeline

This downloads the data, cleans it, trains the model, and saves it to `model/`:

```bash
python pipeline.py
```

Expected output:

```
=== Phase 1: Data Wrangling ===
Downloading dataset...
Anomaly rate: 19.0%  (5365 / 28187 rows)
Saved  train=19730  test=5638  sample=2819 rows

=== Phase 2: Model Training ===
  Accuracy  : 1.0000
  Precision : 1.0000
  Recall    : 1.0000  <- primary
  F1        : 1.0000
  ROC-AUC   : 1.0000  <- primary
  Model saved  model/wind_turbine_model.joblib

Pipeline complete.
```

### 4. Start the API

```bash
uvicorn src.api.main:app --port 8001 --reload
```

The API is now available at `http://localhost:8001`.

> To suppress the per-request `INFO` log noise add `--log-level error` — only
> errors and critical messages will be printed.

## Deploy to a Remote Server

The recommended layout on a Linux server is `/opt/wind_turbine_assessment/` —
conventional for self-contained third-party applications. The source is only needed
at build time; once the Docker image is built the container is self-sufficient.

### 1. Transfer the project (run on your local machine)

```bash
scp -i /path/to/key.pem -r ./wind_turbine_assessment jkl@<server-ip>:/tmp/wind_turbine_assessment
```

### 2. SSH into the server

```bash
ssh -i /path/to/key.pem jkl@<server-ip>
```

### 3. Move to /opt and install Docker

```bash
sudo mv /tmp/wind_turbine_assessment /opt/wind_turbine_assessment

sudo apt update && sudo apt install -y docker.io
sudo systemctl enable --now docker
```

### 4. Set up Kaggle credentials

Required only for the build step — the trained model is baked into the image
and credentials are not needed afterwards.

```bash
mkdir -p ~/.kaggle
nano ~/.kaggle/kaggle.json   # paste {"username":"...","key":"..."}
chmod 600 ~/.kaggle/kaggle.json
```

### 5. Build the image

```bash
cd /opt/wind_turbine_assessment
sudo docker build -t wind-turbine-assessment .
```

### 6. Run the container

```bash
sudo docker run -d \
  --name wta \
  --restart unless-stopped \
  -p 8001:8001 \
  wind-turbine-assessment
```

`-d` runs the container in the background so it survives when the SSH session closes.
`--restart unless-stopped` brings it back automatically after a server reboot.

### 7. Verify

```bash
sudo docker ps           # confirm the container is running
sudo docker logs wta     # check startup output
```

The API is now reachable at `http://<server-ip>:8001`.

> After a successful build you can remove `~/.kaggle/kaggle.json` from the server —
> it is no longer needed.

### `POST /api/v1/predict`

Runs the model against a single sensor reading.

```bash
curl -X POST http://localhost:8001/api/v1/predict \
  -H "Content-Type: application/json" \
  -d '{
    "turbine_id": "TRB-042",
    "measurement_timestamp": "20260425_120000",
    "temperature": 95.4,
    "humidity": 88.1,
    "noise_level": 78.3
  }'
```

**Request fields**

| Field                   | Type   | Constraints           | Description                |
| ----------------------- | ------ | --------------------- | -------------------------- |
| `turbine_id`            | string | non-empty             | Unique turbine identifier  |
| `measurement_timestamp` | string | `yyyymmdd_hhmmss` UTC | Time the reading was taken |
| `temperature`           | float  | ≥ 0.0                 | Generator temperature (°C) |
| `humidity`              | float  | 0.0 – 100.0           | Relative humidity (%RH)    |
| `noise_level`           | float  | ≥ 0.0                 | Noise level (dB)           |

**Response `200 OK`**

```json
{
  "turbine_id": "TRB-042",
  "measurement_timestamp": "20260425_120000",
  "response_timestamp": "20260425_120001",
  "potential_anomaly": true,
  "probability": 0.87
}
```

| Field                | Type    | Description                            |
| -------------------- | ------- | -------------------------------------- |
| `potential_anomaly`  | boolean | `true` if the model predicts a failure |
| `probability`        | float   | Failure probability [0.0, 1.0]         |
| `response_timestamp` | string  | UTC time the prediction was generated  |

---

### `POST /api/v1/predict/batch`

Runs the model against a list of readings (e.g. from a parquet export). Each item is
validated and scored independently — invalid items return an error entry without
rejecting the rest of the batch.

**Limits:** maximum **10,000 items** per call (configurable via `MAX_BATCH_SIZE` env var).

```bash
curl -X POST http://localhost:8001/api/v1/predict/batch \
  -H "Content-Type: application/json" \
  -d '[
    {
      "turbine_id": "TRB-042",
      "measurement_timestamp": "20260425_120000",
      "temperature": 95.4,
      "humidity": 88.1,
      "noise_level": 78.3
    },
    {
      "turbine_id": "TRB-043",
      "measurement_timestamp": "20260425_120001",
      "temperature": 45.0,
      "humidity": 50.0,
      "noise_level": 55.0
    }
  ]'
```

**Response `200 OK`**

```json
{
  "total": 2,
  "succeeded": 2,
  "failed": 0,
  "results": [
    {
      "index": 0,
      "turbine_id": "TRB-042",
      "measurement_timestamp": "20260425_120000",
      "response_timestamp": "20260425_120001",
      "potential_anomaly": true,
      "probability": 0.87
    },
    {
      "index": 1,
      "turbine_id": "TRB-043",
      "measurement_timestamp": "20260425_120001",
      "response_timestamp": "20260425_120001",
      "potential_anomaly": false,
      "probability": 0.03
    }
  ]
}
```

### Error Responses

All errors follow a uniform envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "humidity must be between 0.0 and 100.0",
    "timestamp": "20260425_120001"
  }
}
```

| Status | Code                  | Trigger                              |
| ------ | --------------------- | ------------------------------------ |
| `422`  | `VALIDATION_ERROR`    | Missing field or value out of range  |
| `422`  | `BATCH_SIZE_EXCEEDED` | Batch exceeds `MAX_BATCH_SIZE`       |
| `503`  | `MODEL_NOT_READY`     | Model file failed to load at startup |
| `500`  | `PREDICTION_FAILED`   | Unexpected error during inference    |

## Integration with windmill_scanner

This service is designed to run as a third process inside the
[windmill_scanner](../windmill_scanner) Docker container alongside its FastAPI backend
and nginx reverse proxy.

**supervisord configuration** (add to `windmill_scanner/deploy/supervisord.conf`):

```ini
[program:assessment]
command=uvicorn src.api.main:app --host 127.0.0.1 --port 8001 --workers 1
directory=/app/assessment
autostart=true
autorestart=true
stdout_logfile=/dev/fd/1
stdout_logfile_maxbytes=0
stderr_logfile=/dev/fd/2
stderr_logfile_maxbytes=0
startsecs=2
```

**Call contract:**

- Called synchronously on every sensor beat: `POST http://localhost:8001/api/v1/predict`
- On failure (timeout / service unavailable): the sensor reading is saved with
  `potential_anomaly = null` and `probability = null` — the beat is never lost
- Results are persisted in the scanner's `sensor_readings` table via two nullable
  columns: `potential_anomaly` (boolean) and `probability` (float)

## Dataset

Source: [HackerEarth Machine Learning Challenge](https://www.kaggle.com/datasets/mukund23/hackerearth-machine-learning-challenge)
on Kaggle (`mukund23/hackerearth-machine-learning-challenge`).

Only `generator_temperature(°C)` is retained from the 22 raw columns. `humidity` and
`noise_level` are simulated sensor columns imputed with a fixed random seed for full
reproducibility.
